# المراجعة الأمنية الأولية للنقل

**النطاق:** مراجعة ساكنة للأرشيف المنقول، وليست اختبار اختراق كاملًا أو شهادة أمان. لم تُشغّل خدمات المصدر ولم تُفحص أهداف خارجية.

## نتائج رئيسية

### 1. تنفيذ أوامر دون مصادقة/تفويض واضحين — حرج

أمثلة في المصدر الموروث:

- `artifacts/api-server/src/routes/terminal.ts`: يقبل أمرًا ويمرره إلى `exec`.
- `artifacts/api-server/src/routes/exec.ts` و`shell.ts`: مسارات تشغيل أوامر.
- `artifacts/api-server/src/routes/local-agent.ts`: تحكم بالملفات والعمليات وWebSocket.
- `artifacts/api-server/src/routes/mcp.ts`: يعرض أدوات تنفيذ وتحكم عبر JSON-RPC/webhook.
- `artifacts/api-server/src/app.ts`: يركّب المسارات دون طبقة مصادقة عامة ظاهرة في الملف.

**الأثر:** تعريض الخادم أو الأجهزة المتصلة لتنفيذ غير مصرح به إذا نُشر كما هو.

**الإجراء في النقل:** عزل نقطة التشغيل القديمة، وتوجيه التشغيل الافتراضي إلى لوحة آمنة لا تنفذ أوامر. هذا لا يؤمّن كل ملف موروث؛ ما زالت الملفات موجودة للمراجعة والتطوير.

### 2. أسرار وعناوين تشغيل خاصة — عالٍ

وُجدت قيم مضمنة لتوكن Telegram، ومعرّف محادثة، وتوكن بوابة OpenClaw، وعناوين نفق خاصة، وwebhook إشعارات في بيانات البذر. لم تُنشر القيم في الوثائق أو السجلات.

**الإجراء في النقل:** إزالة القيم من النسخة المنقولة، وإلغاء بذر webhooks، واستبعاد الحزم المبنية وخرائط المصدر التي قد تحمل نسخًا من القيم. يجب على المالك إلغاء/تدوير الأسرار من خدماتها؛ الحذف من Git لا يبطلها.

### 3. قابلية SSRF ووصول لأهداف غير مقيدة — عالٍ

- `routes/scanner.ts` يقبل URL ويتبع إعادة التوجيه.
- `routes/security/scan.ts` و`lib/security-tools.ts` يقبلان أهدافًا ويشغلان فحوصًا/أدوات.
- مسارات proxy وملفات/تنزيل تحتاج مراجعة منفصلة.

**الإجراء:** لا تشغيل خارجي. المطلوب لاحقًا: تطبيع الهدف، منع العناوين الخاصة والمحلية، تثبيت DNS/التحقق من كل إعادة توجيه، وقائمة نطاقات مصرح بها.

### 4. نتائج محاكاة قد تُفهم كحقائق — عالٍ من ناحية سلامة المنتج

- `routes/nuclei.ts` يعيد نتائج CVE ثابتة عند غياب الأداة.
- بعض وحدات agent تستخدم محاكاة أو fallback.
- بيانات البذر تتضمن حالات نجاح ومهامًا وأمثلة ليست بالضرورة تشغيلًا فعليًا.

**الإجراء:** كل نتيجة مستقبلية يجب أن تحمل `mode: live|simulated|inferred` ومصدرًا ودليلًا. لا تُعرض المحاكاة كنتيجة حقيقية.

### 5. اتساع صلاحيات التشغيل والمهام — عالٍ

الكود يدمج تشغيل shell، تثبيت أدوات، مهام مجدولة، قراءة ملفات، واتصالات خارجية في نفس العملية. هذا يجعل الخطأ الواحد واسع الأثر.

**الإجراء:** مشغّل منفصل بأقل صلاحية، قائمة أدوات وإجراءات مسموحة، وسائط منفصلة عن shell، حدود موارد ومهلة، وعزل شبكة/نظام ملفات.

## تنبيهات الاعتماديات بعد النشر

فعّلنا Dependabot، ورصد 88 تنبيهًا مفتوحًا على الاعتماديات الموروثة: 12 حرجة، 42 عالية، 26 متوسطة، 8 منخفضة. أغلبها في `pnpm-lock.yaml` و`package.json` وملف حزم API القديم. هذه التنبيهات لا تعني أن كل حزمة مستغلة فعليًا، لكنها سبب إضافي لعدم تشغيل النسخة القديمة قبل التحديث والمراجعة. لم نثبّت أو نحدّث هذه الحزم في جلسة النقل.

## ما لم نفحصه بعد

- سلامة كل اعتمادية في lockfile أو وجود حزم خبيثة بشكل يدوي كامل.
- صحة بناء TypeScript/React أو اكتمال صادرات قاعدة البيانات.
- أمان كل مسار من مسارات API الثمانين بشكل منفصل.
- أمان سجل Git الأصلي؛ المستودع الجديد بدأ بسجل نظيف من المصدر المنقّح.
- إعدادات نشر/استضافة أو صلاحيات خدمات خارجية.

## شروط قبل إعادة تشغيل أي جزء قديم

1. مصادقة قوية وتفويض لكل إجراء ومورد.
2. بوابة نطاق ملزَمة قبل الشبكة وقبل تنفيذ الأداة.
3. إزالة الأسرار من العميل وتدوير القيم المعرضة.
4. عزل المشغّل وتحديد الأدوات والوسائط والموارد.
5. سجل تدقيق وإيقاف طارئ واختبارات فشل آمنة.
6. مراجعة بشرية للنتائج قبل إرسال أي تقرير لبرنامج خارجي.
