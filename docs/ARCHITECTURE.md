# المعمارية المستهدفة والحدود الآمنة

## الوضع الحالي

```text
المستخدم
  │
  ▼
لوحة تحكم آمنة (platform/)
  ├─ حالة النقل والقدرات
  ├─ مكتبة معرفية محلية
  └─ تحقق محلي من سجل النطاق
       └─ لا اتصال بالهدف، لا تنفيذ أوامر

الكود الموروث (artifacts/ + lib/)
  └─ معزول عن التشغيل الافتراضي
```

## الوضع المستهدف تدريجيًا

```text
واجهة
  ▼
مصادقة + تفويض + سياسة نطاق
  ▼
منسق مهام (قائمة انتظار، حدود، إلغاء)
  ▼
مشغّل معزول بأقل صلاحية
  ├─ وحدات قراءة سلبية أولًا
  ├─ أدوات مصرح بها بإصدارات مثبتة
  └─ أدلة خام + نتائج مُطبّعة
  ▼
مراجعة بشرية + تقرير + سجل تدقيق
```

## قواعد غير قابلة للتفاوض

- الواجهة لا تحمل أسرار خدمات ولا تنفذ أوامر مباشرة.
- النموذج يقترح ويشرح؛ لا يملك صلاحية تنفيذ غير مقيدة.
- كل مهمة تحمل معرف برنامج، أصل، مرجع تفويض، انتهاء صلاحية، نوع اختبار، وحدود موارد.
- رفض افتراضي لأي أصل غير مطابق، وأي إعادة توجيه تخرج عن النطاق.
- فصل النتائج المؤكدة عن المحتملة وعن المحاكاة.
- لا إرسال تلقائي لتقارير إلى برامج خارجية دون مراجعة.
- تحديثات المعرفة من مصادر موثوقة مع وقت مزامنة ومصدر، وليس ادعاء «كل شيء لحظي».

## التكاملات المستقبلية

- GitHub: مستودعات وصلاحيات دقيقة وسجل تقدم؛ لا توكنات واسعة دائمة في الكود.
- HackerOne: قراءة سياسة البرنامج/النطاق عبر واجهة متاحة ومصرح بها إن توفرت، مع مراجعة بشرية. لا افتراض أن كل برنامج أو أصل مسموح.
- مزودو AI: مفاتيح على الخادم فقط، ميزانيات وحدود، وعدم إرسال أسرار أو بيانات أهداف حساسة دون موافقة.
- أدوات Linux: catalogue بإصدارات وتراخيص وقدرات، وليس تثبيتًا عشوائيًا من الإنترنت.
